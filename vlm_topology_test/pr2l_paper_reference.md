# PR2L 논문의 Habitat ObjectNav 설정과 결과

이 문서는 우리 실험이 따르고 있는 선행 연구의 원문을 직접 확인한 기록이다. 지금까지 이
저장소 안에서 "논문에서는 이렇게 했다"고 인용되어 온 내용은 사수님이 정리한 요약 노트를
근거로 한 것이었고, 원문과 어긋나는 부분이 있었다. 아래는 원문(본문 4.2절, 부록 C·D)에서
직접 확인한 사실만 담는다.

**대상 논문.** Chen, Mees, Kumar, Levine. *Vision-Language Models Provide Promptable
Representations for Reinforcement Learning*. arXiv:2402.02651. 저장소 사본은
`docs/papers/PR2L_arxiv_2402.02651.pdf`.

**PR2L이란.** 학습하지 않고 고정해 둔 시각-언어 모델(vision-language model, 이하 VLM)에
과제와 관련된 질문을 던지고, 그 질문에 답하는 과정에서 모델 내부에 생기는 표현을 꺼내
정책(policy)의 입력으로 쓰는 방법이다. 여기서 "표현"은 모델이 각 입력 위치마다 층별로
만들어 내는 벡터를 뜻하고, "정책"은 그 표현을 받아 다음 행동을 고르는 별도의 작은
신경망을 뜻한다. VLM 자체는 전혀 학습되지 않는다.

## 1. 무엇을 성공으로 쳤고, 얼마나 성공했는가

성공 기준은 Habitat의 HM3D ObjectNav 기본 설정을 그대로 쓴다. 즉 **목표 물체의 관찰
지점(view point)으로부터 측지 거리 0.1 m 이내에서 에이전트가 스스로 정지(STOP) 행동을
냈을 때** 성공이다. 이는 우리가 3단계 실험에서 쓰고 있는 기준과 같다.

Habitat ObjectNav 검증 장면 2000 에피소드에 대한 성공률은 다음과 같다.

| 목표 물체 (에피소드 수) | PR2L (CoT 사용) | PR2L (CoT 미사용) | VLM 이미지 인코더 | VC-1 CLS (120 epoch) | VC-1 패치 (120 epoch) |
|---|---|---|---|---|---|
| **전체 (2000)** | **41.9 %** | 27.8 % | 11.6 % | 8.9 % | 15.8 % |
| 변기 (398) | 37.2 % | 22.9 % | 8.8 % | 2.0 % | 9.3 % |
| 침대 (433) | 45.0 % | 28.9 % | 12.9 % | 9.9 % | 19.2 % |
| 소파 (376) | 48.1 % | 34.3 % | 11.7 % | 14.4 % | 19.4 % |
| 의자 (428) | 51.2 % | 40.9 % | 17.5 % | 15.0 % | 23.8 % |
| 텔레비전 (281) | 26.7 % | 10.3 % | 5.0 % | 3.2 % | 4.6 % |
| 화분 (84) | 23.8 % | 8.3 % | 9.1 % | 1.2 % | 9.5 % |

여기서 **CoT**(chain of thought, 사고 연쇄)란 VLM에게 판단만 시키지 않고 그 근거까지 말로
풀어내게 한 뒤 그 생성된 문장의 표현까지 정책에 넘기는 방식을 말한다. 논문이 실제로 쓴
질문은 **"Would a [목표 물체] be found here? Why or why not?"** 이고, 뒤의 "Why or why
not?"이 곧 CoT에 해당한다. 표에서 보듯 이 한 문장의 유무가 41.9 % 대 27.8 %로 성능을
1.5배 갈랐다.

비교 대상인 **VLM 이미지 인코더**는 같은 VLM의 시각 부분만 떼어내 쓴 것으로, 질문을 주지
않으므로 목표 물체를 모른다. 11.6 %에 그친다. **VC-1**은 로보틱스용으로 사전학습된 범용
시각 표현이다. 즉 PR2L의 이득은 "더 좋은 시각 특징"이 아니라 "질문에 조건화된 표현"에서
온다는 것이 논문의 주장이다.

## 2. 강화학습인가 모방학습인가

**주 실험은 모방학습(behavior cloning, BC)이다.** 위 표의 수치는 전부 BC로 얻은 것이다.
논문은 선행 연구와의 비교 가능성을 위해 BC를 택했다고 명시한다.

강화학습은 **별도의 단순화된 설정**에서만 돌렸다(부록 D). 이 설정은 목표 물체를 변기·침대·
소파 셋으로 줄이고, 장면을 32개로 줄이고, 정책에서 과거 이력을 없애 현재 관찰과 자세만
보고 행동하게 만든 것이다. 여기서 PR2L은 **60.4 %**, VLM 이미지 인코더는 35.2 %를 얻었다.

이 단순화된 강화학습 설정의 데이터 수집 방식이 우리와 같다는 점이 중요하다. 논문은
**Habitat 내장 최단 측지 경로 추종기(shortest geodesic path follower)로 시연을 만들고**,
경로의 무작위 지점(0~90 % 구간) 이후부터 0~50 % 확률로 무작위 행동을 섞어 저품질 데이터를
보강했다. 우리가 `nav_baseline/collect.py`에 만들어 둔 교란 주행 방식과 같은 착상이다.
총 2364 궤적, 107,518 관찰이다.

## 3. VLM에서 표현을 정확히 어떻게 꺼냈는가

우리가 3단계에서 구현한 방식과 대부분 일치하지만, **한 군데가 빠져 있다.**

| 항목 | 논문 | 우리 3단계 (`encode.py`) |
|---|---|---|
| VLM | Prismatic, DINOv2+SigLIP 시각 + Llama-2-7B 언어, **224px** | 같은 계열이나 **384px** ← 차이 |
| 시각 토큰 | **256개**(16×16)를 4×4 커널 평균 풀링으로 **16개**로 축소 | **729개**(27×27)를 적응형 풀링으로 16개 ← 차이 |
| 사용 층 | **마지막 두 층** | 같음 |
| 두 층 결합 | 토큰마다 두 층을 이어 붙여 폭 2048 | 이어 붙여 폭 **8192** |
| **차원 축소** | **주성분분석(PCA)으로 4096 → 1024** | **없음** ← 차이 |
| 텍스트 토큰 | 질문과 생성 답변의 **모든 위치**를 그대로 정책에 전달 | 4개로 풀링 ← 차이 |
| 답변 생성 | 표본 추출, 온도 0.4, 새 토큰 32~48개 | 탐욕적 선택, 48개 ← 차이 |

**주성분분석(PCA)**이란 데이터가 실제로 퍼져 있는 방향만 골라 남기고 나머지를 버려 벡터의
길이를 줄이는 방법이다. 논문은 각 궤적에서 관찰 하나씩을 무작위로 뽑아 인코딩한 뒤 그
토큰들로 주성분 방향을 구하고, 그 방향으로 모든 토큰을 4096차원에서 1024차원으로 줄였다.
우리 3단계는 이 단계를 건너뛰어 토큰 폭이 8192이며, 이는 논문의 4배다. 시연 수가 논문의
1/47인 상황에서 입력 폭만 4배로 넓으므로 과적합에 훨씬 취약하다.

**정책 구조.** 프레임 하나가 만들어 내는 토큰 수가 매번 다르기 때문에, 논문은 학습되는
Transformer 층 하나를 두고 **"CLS"라 부르는 학습된 질의 토큰 하나**가 그 프레임의 토큰들을
주목(attention)해 고정 길이 벡터 하나로 요약하게 한다. 시간 축은 그 위에 **LSTM**(과거를
은닉 상태에 담아 순차적으로 읽는 순환 신경망)을 얹어 처리한다. 우리 3단계는 프레임 내
요약은 같은 방식이지만 시간 축을 인과 마스킹 Transformer로 처리한다. 논문은 구조 차이가
결과를 오염시키지 않도록 모든 비교 대상에 같은 정책 구조를 쓴다고 명시했으므로, 이
차이 자체는 문제가 아니다.

## 4. 관찰 공간과 데이터 규모

**관찰 공간.** 부록 C.1이 열거하는 항목은 다섯이다.

1. RGB 이미지 (480×640×3)
2. **위치** — 에이전트의 수평 좌표 2개
3. **나침반** — 에이전트의 방위각 1개
4. 직전 행동 — 4차원 one-hot
5. 목표 물체 — one-hot

본문 4.2절은 "RGB와 직전 행동과 목표 물체만 쓰고 깊이 영상은 뺐다"고 적고 있으나, 부록의
목록에는 **위치와 나침반이 포함되어 있다.** 이는 Habitat ObjectNav 기본 설정에 GPS 센서와
나침반 센서가 들어 있기 때문이며, 논문이 그 기본값을 따랐다고 밝힌 것과 일치한다. 즉
정책은 자기가 어디에 있고 어느 쪽을 보는지를 알고 있다. 깊이 영상만 제거된 것이다.

**행동 공간.** 좌/우 회전 30°, 전진 고정 거리, 정지의 네 가지. 고개를 위아래로 드는
행동은 제거했다. 우리와 같다.

**데이터 규모.** Habitat-Web 사람 시연 데이터셋(77,000 궤적, 1200만 스텝) 중 **목표 물체와
장면 조합별로 열 개당 하나씩 뽑아 7550 궤적, 약 110만 스텝**을 썼다. 학습 장면 80개,
검증 장면 20개이며 **평가는 학습에서 본 적 없는 검증 장면**에서 한다.

**난이도의 척도.** 논문은 이 과제가 특권적 최단 경로 추종기 기준 **80스텝**, 사람 기준
150스텝 이상이 걸리는 장기 과제라고 밝힌다.

**학습 세부.** 학습률 1e-4, 배치는 궤적 전체 단위, 약 40 epoch(약 4000만 전이). 손실은
행동이 바뀌는 순간을 가중(inflection upweighting)하고, **정지와 회전의 교차 엔트로피를
1.5배 가중**한다. 이미지 증강이나 정규화는 쓰지 않았다. 우리 3단계 `train.py`의 가중치
설정은 이와 같다.

## 5. 우리 실험과의 차이 정리

| 항목 | 논문 | 우리 3단계 |
|---|---|---|
| 시연 수 | 7550 궤적 / 110만 스텝 | 160 궤적 / 약 6천 스텝 (규칙당) |
| 시연 출처 | 사람 (Habitat-Web) | 최단 경로 추종기 |
| 장면 | 학습 80개, 평가는 미지의 20개 | 8개 경로, 학습과 평가가 같은 경로 |
| 관찰 | RGB + 위치 + 나침반 + 직전 행동 + 목표 | RGB만 |
| 토큰 폭 | 2048 (PCA 후) | 8192 (PCA 없음) |
| 성공 기준 | 0.1 m | 0.1 m (같음) |
| 전체 성공률 | 41.9 % | — |

우리 설정은 경로를 고정하고 학습과 평가를 같은 경로에서 하므로 일반화를 요구하지 않는
대신 시연 수가 논문의 1/47이다. 관찰에서 위치와 나침반이 빠져 있는 점은 의도적이다.
우리가 묻는 것은 "VLM 표현만으로 어디로 갈지 정할 수 있는가"이므로 자세 정보를 주면
질문 자체가 성립하지 않는다. 다만 그만큼 논문 수치와 직접 비교할 수 없다는 점은
명시해 두어야 한다.
