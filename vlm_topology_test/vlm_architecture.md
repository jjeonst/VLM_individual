# 이 연구가 쓰는 시각-언어 모델의 구조와 표현 추출 방식

이 문서는 실험에서 쓰는 시각-언어 모델(vision-language model, 이하 VLM)이 어떻게 생겼는지,
그 안의 어느 위치에서 숫자를 꺼내 정책에 넘기는지, 그리고 왜 하필 그 위치인지를 정리한다.
실험 설계와 결과는 [phase3_fixed_route/experiment_results_fixed_route.md](phase3_fixed_route/experiment_results_fixed_route.md)에,
선행 연구와의 대조는 [pr2l_paper_reference.md](pr2l_paper_reference.md)에 있다.

여기 적힌 수치는 모두 설치된 모델과 코드에서 직접 확인한 것이며, 확인 방법은 6절에 적었다.

---

## 1. 모델의 구성

쓰는 모델은 Prismatic의 `prism-dinosiglip+7b` 체크포인트다. 세 부분으로 이루어진다.

```
                     사진 384 × 384
                           │
        ┌──────────────────┴──────────────────┐
        ▼                                     ▼
  DINOv2 ViT-L/14                    SigLIP SO400M/14
  729 토큰 × 1024차원                729 토큰 × 1152차원
        └──────────────────┬──────────────────┘
                           ▼  채널 방향으로 이어 붙임
                   729 토큰 × 2176차원
                           ▼  투영기 (fused-GELU MLP)
                   729 토큰 × 4096차원
                           ▼
   [BOS] [이미지 729] [질문] [생성된 답변]  →  Llama-2-7B (32층, 은닉 4096)
```

**시각 백본이 둘인 것이 이 모델의 특징이다.** DINOv2는 이미지만으로 자기지도 학습한 모델이라
공간 배치와 기하 구조에 강하고, SigLIP은 이미지와 문장을 짝지어 학습한 모델이라 의미 파악에
강하다. 두 모델을 같은 패치 격자로 돌린 뒤 특징을 채널 방향으로 이어 붙여 양쪽 성질을 함께
가져간다. 두 백본의 패치 격자가 27×27로 같기 때문에 이 결합이 가능하다.

**투영기(projector)**는 시각 특징 2176차원을 언어 모델의 입력 차원 4096으로 옮기는 작은
다층 신경망이다. 이 단계를 거치면 이미지 패치가 **언어 토큰과 완전히 같은 형식**이 되므로,
문장 앞에 그냥 끼워 넣을 수 있다.

**언어 백본**은 Llama-2-7B이며 디코더 전용 구조다. 여기서 중요한 성질이 하나 나온다.

## 2. 인과 마스킹 — 정보가 한 방향으로만 섞인다

디코더 전용 언어 모델은 **인과 마스킹(causal masking)**을 쓴다. 각 위치는 자기 자신과 그
이전 위치만 참조할 수 있고 이후 위치는 볼 수 없다. 입력이 아래 순서로 놓이므로,

```
위치   0        1 ─────────── 729      730 ──── 743     744 ────────
      [BOS]  [이미지 패치 729개]      [질문 토큰]      [생성된 답변]
             └── 뒤를 볼 수 없음 ──┘
                                  └─ 앞의 이미지 전체를 봄 ─┘
```

**이미지 위치는 질문보다 앞에 있어서 질문을 참조할 수 없다.** 이는 경향이 아니라 구조적
제약이다.

이 사실은 측정으로 확인했다. 같은 사진을 목표 물체만 바꿔가며(의자·변기·침대·화분) 인코딩해
표현을 비교한 결과는 다음과 같다.

| 추출 위치 | 최대 절대차 | 코사인 유사도 | 판정 |
|---|---|---|---|
| 이미지 토큰 | **0.0** | **1.0** | 목표와 무관하게 완전히 동일 |
| 마지막 토큰 | 9.7 ~ 14.8 | 0.39 ~ 0.51 | 목표에 따라 크게 다름 |

이미지 토큰은 비슷한 정도가 아니라 **비트 단위로 같다.** 같은 프레임에서 모델이 낸 답변을
보면 왜 마지막 토큰이 달라지는지 알 수 있다.

```
의자 → "No, because it is a kitchen."
변기 → "No, a toilet is not found in the kitchen."
화분 → "Yes, a plant could be found in the corner of the room for decoration."
```

같은 부엌 사진인데 목표에 따라 판단이 뒤집힌다. 이 판단은 질문 이후 위치에만 존재한다.

원자료는 `phase2_representation_redesign/results/goal_conditioning_check.json`에 있다.

### 위치마다 담긴 정보가 다른 이유

| 추출 위치 | 담고 있는 것 | 담고 있지 않은 것 |
|---|---|---|
| 이미지 토큰 | 화면의 공간 배치 (좌·우, 원·근) | 목표가 무엇인지 |
| 텍스트 토큰 | 목표 조건부 판단 (여기 있을 만한가, 왜) | 공간 배치의 세부 |

이미지 토큰끼리도 서로 다른데, 두 가지가 작동한다. 첫째는 **위치 고정**이다. 각 이미지 위치는
패치 격자의 특정 칸이 투영되어 들어간 자리이고, 트랜스포머는 잔차 연결을 쓰기 때문에 주목
결과가 기존 벡터를 대체하지 않고 더해진다. 그래서 다른 위치의 정보가 섞인 뒤에도 자기 패치의
기여가 남는다. 둘째는 이미지 위치끼리도 인과 마스킹이 적용된다는 점으로, 래스터 순서상 뒤쪽
패치는 앞쪽을 보지만 그 반대는 아니다.

다만 정확히 하면, 시각 백본 자체는 양방향이므로 언어 모델에 들어오기 **전에** 이미 각 패치
임베딩이 이미지 전역 맥락을 담고 있다. 따라서 "위치 *i* 는 영역 *i* 만 담는다"는 근사이고,
"영역 *i* 에 고정되어 있되 전역 맥락도 함께 가진다"가 정확한 표현이다.

## 3. 어느 토큰을 꺼내는가

언어 모델을 통과시킬 때 모든 층의 은닉 상태를 받아(입력 임베딩 + 32층 = 33개) 그중 **마지막
두 층**만 쓴다. 한 층의 출력은 `[전체 위치 수, 4096]` 형태이며, 위치를 셋으로 나눈다.

| 구간 | 위치 | 처리 |
|---|---|---|
| `[BOS]` | 0 | 버린다 |
| 이미지 | 1 ~ 729 | 16개로 압축 |
| 질문 + 생성된 답변 | 730 ~ 끝 | 4개로 압축 |

마지막 두 층을 쓰는 것은 선행 연구를 따른 것이다. 층이 깊어질수록 시각 토큰의 표현이 어휘
공간에서 해석 가능해진다는 보고가 있으며(6절 참고 문헌), 그 관점에서도 마지막 층 쪽이
과제와 관련된 판단을 담고 있다.

## 4. 어떻게 압축하는가

### 4.1 이미지: 27×27 격자를 4×4로

이미지 위치 729개는 원본 사진의 패치 격자를 래스터 순서로 편 것이므로 정사각 격자로 되돌릴
수 있다.

```
[729, 4096] → [27, 27, 4096] → 적응형 평균 풀링 → [4, 4, 4096] → [16, 4096]
```

각 토큰이 사진의 한 구역을 담당하므로 **좌·우와 원·근 구조가 살아남는다.** 어느 통로로
들어갈지를 정하려면 이 정보가 필요하다.

27을 4로 나누면 떨어지지 않으므로 구역 크기가 6에서 7 사이로 들쭉날쭉하다. 이는 선행 연구와
다른 점이며 5절에서 다룬다.

### 4.2 텍스트: 가변 길이를 4개로

질문과 답변의 길이는 매번 다르다(답변은 32~48 토큰). 정책은 고정 크기 입력을 받아야 하므로
길이 방향으로 균등하게 넷으로 나누어 평균한다.

```
[가변, 4096] → 적응형 평균 풀링 → [4, 4096]
```

### 4.3 두 층 결합과 주성분분석

여기까지가 한 층에 대한 처리다. 마지막 두 층에 각각 적용하면 토큰마다 벡터가 둘 생긴다.

```
[20, 2, 4096] → 주성분분석 → [20, 2, 1024] → 층 결합 → [20, 2048]
```

**주성분분석(principal component analysis)**은 데이터가 실제로 퍼져 있는 방향만 남기고
나머지를 버려 벡터를 줄이는 방법이다. 이것이 필요한 이유는 시연 수와 입력 폭의 불균형이다.
시연이 규칙당 160개뿐인데 폭 8192짜리 입력을 그대로 주면 정책이 시연을 외우고도 남는다.

방향은 전체 시연에서 고르게 뽑은 프레임 640장(토큰 표본 25,600개)으로 미리 구해 모든
프레임에 똑같이 적용하고, `pca.npz`로 저장한다. 평가할 때는 화면을 그 자리에서 인코딩하므로
**반드시 같은 방향을 불러 써야 한다.** 그러지 않으면 정책이 학습할 때와 다른 좌표계를 보게
되고, 이는 조용히 성능만 떨어뜨려 원인을 찾기 어렵다.

| 규칙 | 유지된 변동 비율 |
|---|---|
| random | 0.978 |
| matched | 0.980 |
| junction | 0.979 |

차원을 4분의 1로 줄이고도 원래 변동의 98%가 남는다.

### 4.4 전체 흐름

```
사진 384²
  → 729 × 2176   두 시각 백본 결합
  → 729 × 4096   투영기
  → 언어 모델 통과, 마지막 두 층 추출
  → 이미지 729 → 16   (27×27 격자를 4×4로 평균)
     텍스트 가변 → 4   (길이를 넷으로 나누어 평균)
  → 20 × 2 × 4096
  → 20 × 2 × 1024      주성분분석
  → 20 × 2048          정책 입력
```

## 5. 선행 연구와 다른 점

선행 연구(PR2L)도 같은 계열의 Prismatic 모델을 쓰지만 해상도가 다르다.

| 항목 | 선행 연구 | 본 연구 |
|---|---|---|
| 시각 백본 해상도 | 224 px | **384 px** |
| 시각 토큰 수 | 256 (16×16) | **729 (27×27)** |
| 풀링 방식 | 4×4 커널, 스트라이드 4 → 정확히 4×4 | 적응형 풀링 27 → 4 |
| 결과 토큰 수 | 16 | 16 (같음) |
| 토큰 하나가 덮는 패치 | 16개 (균일) | 46~49개 (불균일) |

결과 토큰 수는 16으로 같지만 입력 해상도와 각 토큰이 덮는 영역이 다르다. 384 px 쪽이 시각
정보를 더 많이 담으므로 불리하다고 볼 이유는 없으나, 체크포인트 이름이 같아도 설정이 다르다는
점은 명시해 두어야 한다.

**목표 정보가 텍스트 토큰 4개에만 실린다는 점도 기록해 둔다.** 2절에서 보였듯 이미지 토큰은
목표와 완전히 무관하므로, 목표 조건화는 오직 텍스트 토큰을 통해서만 정책에 전달된다. 20개
중 4개가 그 역할 전부를 맡는 셈이다. 선행 연구는 질문과 생성 답변의 **모든 위치**를 정책에
넘기며, 그 논문의 수치는 이 부분의 비중이 크다는 것을 시사한다.

| 선행 연구의 조건 | 성공률 |
|---|---|
| 시각 특징만 사용 (목표 정보 없음) | 11.6 % |
| 질문과 생성 답변의 표현까지 사용 | 41.9 % |

따라서 **텍스트 토큰 수를 4에서 8, 16으로 늘려 보는 것**이 다음 회차에서 우선순위가 높은
변경이다. 시각 토큰은 그대로 두고 `encode.py`의 `TEXT_TOKENS` 상수만 바꾸면 되며, 인코딩만
다시 하면 된다.

## 6. 확인 방법과 참고 문헌

### 이 문서의 수치를 확인한 방법

| 사실 | 확인처 |
|---|---|
| 백본이 384 px 판 | `/data/topovlm/vlm_weights/prismatic/prism-dinosiglip+7b/config.json`의 `vision_backbone_id = dinosiglip-vit-so-384px` |
| 패치 729개와 격자 27×27, 차원 1024·1152 | `timm.create_model(..., img_size=384)`의 `patch_embed.num_patches`와 `embed_dim` |
| 두 백본 결합과 패치 수 일치 | `prismatic/models/backbones/vision/dinosiglip_vit.py`의 `embed_dim`, `num_patches` |
| 언어 모델 은닉 4096 | `vlm.llm_backbone.llm.config.hidden_size` |
| 이미지 토큰의 목표 무관성 | `phase2_representation_redesign/results/goal_conditioning_check.json` |
| 유지된 변동 비율 | `/data/topovlm/phase3_fixed_route/encoded_*/manifest.json`의 `pca.explained_variance_ratio` |

### 구현 위치

표현 추출은 [phase3_fixed_route/encode.py](phase3_fixed_route/encode.py)에 있다.
`MultiTokenEncoder.encode_layers`가 3절을, `_pool_image`와 `_pool_text`가 4.1·4.2절을,
`Projection`이 4.3절을 담당한다.
